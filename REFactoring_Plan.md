# План поэтапного рефакторинга YouTube Bot

Документ фиксирует цели, принципы, этапы работ и критерии принятия для предстоящего рефакторинга. Используется как рабочий трекер и справочник.

## Цели
- Убрать дублирующуюся логику и данные.
- Унифицировать параметры (`k`, `threshold`, `type`, `channelId`, `showScore`).
- Привести интерфейсы данных к единому формату.
- Сделать обработчики Telegram предсказуемыми и единообразными.
- Улучшить диагностируемость (логи, ошибки, проверки окружения).
- Обновить документацию и сделать поведение бота прозрачным для пользователя и администратора.

## Принципы
- Минимальные и целевые изменения, без «золотого покрытия».
- Единый источник истины для конфигурации и типов.
- Порядок операций: фильтрация → ограничение (`k`) → форматирование → вывод.
- Возврат главного меню после пользовательских действий, где это ожидаемо.
- Не правим нерелевантные баги и не меняем публичное API без явной необходимости.

## Быстрые исправления (выполнено)
- Добавлена кнопка «Закрыть настройки» в `buildSettingsKeyboard` и обработчик `close:settings` → возвращает главное меню.
- Добавлен общий обработчик `bot.on('message')` → для любых сообщений показывает основное меню.
- Исправлен порядок в «Последние»: `type`-фильтрация до `k` (в `fetchLatestVideos` + упрощён хендлер `🆕 Последние`).
- Обновлён текст помощи (ранее): упор на клавиатуру, без слэш-команд; `k` конфигурируется до `SEARCH_MAX_K`.
- Скрытая команда `/admin` (ранее): листинг доступных админ-команд для `env.ADMIN_USER_ID`.

### Проверка выполненных исправлений
- «Настройки» → «Закрыть настройки»: закрывает инлайн-клавиатуру, показывает главное меню.
- Любое сообщение вне режима поиска: бот отвечает «Выберите действие…» с главным меню.
- «Последние» при выбранном `type` и `k`: выводит ровно `k` видео нужного типа.

## Этапы рефакторинга

### Этап 1. Конфигурация и валидация окружения
- Централизовать доступ к `env` в `src/config/env.js`; описать обязательные ключи.
- Ввести раннюю валидацию: наличие `TELEGRAM_BOT_TOKEN`, `YOUTUBE_API_KEY`, корректность диапазонов `k`, `threshold`.
- Зафиксировать единые имена: `SEARCH_MAX_K`, `SEARCH_MAX_DISTANCE`, и использовать их везде.
- Артефакты: схема `env`, проверка при старте, понятные сообщения об ошибках.
- Критерии: отсутствие расхождений имён, единая точка проверки.

### Этап 1a. Модели и эмбеддинги: переключаемый провайдер
- Ввести абстракцию `EmbeddingsProvider` с единым интерфейсом: `embed(texts) => float[][]`.
- Поддерживаемые провайдеры: `mistral`, `google` (Vertex/Generative Language), `xenova` (локально, без сети).
- Быстрое переключение через `EMBEDDINGS_PROVIDER` и `EMBEDDINGS_MODEL_ID`; цепочка фоллбэков через `EMBEDDINGS_PROVIDER_CHAIN` (например, `mistral,xenova`).
- Конфигурация провайдеров в `.env`: `MISTRAL_API_KEY`, `GOOGLE_API_KEY/Vertex`, `EMBEDDINGS_MODEL_ID`, `EMBEDDINGS_DIM?`.
- Стабилизация загрузки: `EMBEDDINGS_MAX_CONCURRENCY`, `EMBEDDINGS_BATCH_SIZE`, `EMBEDDINGS_TIMEOUT_MS`, `EMBEDDINGS_MAX_ATTEMPTS` + экспоненциальный бэкофф.
- Обработка квот/503: автоматический переход на следующий провайдер, подробное логирование причины и провайдера.
- Кэширование эмбеддингов (ключ: `provider|model|textHash`) для повторного использования и снижения затрат.
- Диагностика: команда/скрипт самопроверки и предпросмотра, вывод размерности и времени выполнения на каждом провайдере.
- Критерии: смена провайдера без изменений остального кода; предсказуемая деградация при перегрузках.

### Этап 2. Интерфейсы данных видео
- Единый тип: `{ id, title, description, url, type, channelId?, publishedAt?, score? }`.
- Привести нормализацию описаний и `deriveType` к одному месту (`services/youtube/classify`, `services/text/*`).
- Убрать дубли нормализации в скриптах индексации.
- Критерии: все места получения видео возвращают один тип.
- Выполнено: централизована нормализация; `toVideoEntity` используется в `index_latest_10.js`, `preview_latest_10.js`, `index_batch.js` и `fetchLatestVideos` в `src/index.js`.

### Этап 3. Хранилище настроек пользователя
- Проверить/привести `settings_store`: типы и дефолты (`k ≥ 1`, `k ≤ SEARCH_MAX_K`, числовой `threshold`).
- Единообразно применять настройки в `Поиск`, `Последние`, `Настройки`, `Помощь`.
- Критерии: одинаковая трактовка настроек во всех хендлерах.
- Выполнено: нормализация `settings_store` (кламп `k`, числовой `threshold`, валидный `type`), единообразное применение во всех хендлерах; добавлены юнит‑тесты на нормализацию.

### Этап 4. Логика «Последние»
- Закреплён порядок: выбор канала → ids → детали → `type`-фильтр → `slice(0, k)` → форматирование → вывод.
- Вынесена сервис-логика: `src/services/youtube/latest.js` (`fetchLatestVideos`, `applyOrderingForLatest`).
- Хендлер `🆕 Последние` использует сервис `fetchLatestVideos`.
- Юнит‑тесты: `tests/latest_flow.test.js` проверяет `type`‑фильтр до `slice(k)`.
- Проверены скрипты (`index_latest_10.js`, `preview_latest_10.js`) на согласованность.
- Критерии: зелёные тесты; отсутствие пост‑фильтрации после `slice`; одинаковый результат при одинаковых входных.

### Этап 5. Поиск (LanceDB)
- Унификация метрики: один ключ `score` (адаптация `_distance|distance → score`).
- Вынесено конструирование поиска: `src/services/vector/search.js` (`clampK`, `normalizeThreshold`, `normalizeType`, `searchUnified`).
- Хендлер поиска в `src/index.js` переключён на `searchUnified`; форматирование осталось через `formatSearchItem`, показ `score` управляется `showScore`.
- Юнит‑тесты: `tests/search_params.test.js` проверяет нормализацию параметров и унификацию метрики.
- Критерии: зелёные тесты; единая метрика `score` во всех путях; предсказуемый формат вывода.

### Этап 6. Обработчики Telegram
- Ревизия всех `bot.hears`/`bot.on`/`bot.command`: единый стиль текстов и возврата клавиатуры.
- Централизовать показ главного меню (общий обработчик + минимизация дублей в специфических местах).
- Критерии: нет повторных сообщений меню; предсказуемые переходы.
- Прогресс: вынесены клавиатуры и коллбеки (keyboards/callbacks), централизован `pendingInputs`, удалён legacy `buildSettingsKeyboardLegacy`, добавлены базовые тесты на клавиатуры/коллбеки; устранены дубли меню в catch‑all (игнор известных кнопок и режима ввода).

### Этап 7. Форматирование вывода
- Один форматтер для «Последние» и один для поиска; `showScore` управляет показом балла.
- Критерии: отсутствие разночтений, удобочитаемость.
- Прогресс: `score` округляется до 6 знаков; результаты поиска нумеруются; обновлён `formatSearchItem`; добавлены юнит‑тесты; прогон `npm run test:ci` зелёный.

### Проверка Этапа 7
- Поиск при `showScore = true`: результаты нумеруются (`1.`, `2.`, …); `score` показывается с 6 знаками; присутствуют строки `date: YYYY-MM-DD` и `type: ...`.
- Поиск при `showScore = false`: строка `score:` отсутствует; остальной формат идентичен.
- «Последние»: вывод через `formatLatestItem` — `title`, `url`, `type` и нормализованное описание; описание обрезается по `DESC_MAX_CHARS`, удаляет рекламные префиксы (`INDEX_DESC_AD_LINE_PREFIX_CHARS`) и текст после паттернов (`INDEX_DESC_STRIP_AFTER_PATTERNS`).
- Длинные сообщения: разбиение по лимиту ~3800 символов выполняется функцией `splitTextByLimit` без разрывов слов.
- Диагностика: `npm run test:ci` зелёный; тест `tests/telegram_format.test.js` проверяет округление `score` и скрытие поля при `undefined`.

### Этап 8. Админ-команды
- Перечень операций и единый роутер исполнения: блокировки/статистика/таблицы/проверки/индексации.
- Проверка доступа по `env.ADMIN_USER_ID`, единые ответы об успехе/ошибках.
- Критерии: корректный контроль доступа, стабильный вывод.

### Проверка Этапа 8
- Доступ: команды отвечают только администратору (`env.ADMIN_USER_ID`), для не‑админа — отказ.
- Покрытие роутера: `/lock_status`, `/lock_force`, `/channel_db_list`, `/channel_db_delete <channel> --yes`, `/channel_stats [channel]`, `/channel_count [channel]`, `/check_youtube [channel]`, `/index_latest [channel]`, `/index_batch [channel] [--limit N] [--stop-on-first-known on|off]`, `/preview_latest` (только .env), `/search_latest <query>`, `/env_check`.
- Вывод: длинный ответ режется функцией `splitTextByLimit`, ошибки и коды завершаются единообразно.
- Аргументы/флаги: токены команд передаются полностью и в исходном порядке; `--limit` и `--stop-on-first-known` корректно доходят до `index_batch.js`.
- Реализация: новый модуль `src/services/admin/router.js`, регистрация в `src/index.js`.
- Тесты: `tests/admin_router.test.js` для парсинга аргументов; прогон `npm run test:ci` зелёный.
