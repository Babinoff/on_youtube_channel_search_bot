# План поэтапного рефакторинга YouTube Bot

Документ фиксирует цели, принципы, этапы работ и критерии принятия для предстоящего рефакторинга. Используется как рабочий трекер и справочник.

## Цели
- Убрать дублирующуюся логику и данные.
- Унифицировать параметры (`k`, `threshold`, `type`, `channelId`, `showScore`).
- Привести интерфейсы данных к единому формату.
- Сделать обработчики Telegram предсказуемыми и единообразными.
- Улучшить диагностируемость (логи, ошибки, проверки окружения).
- Обновить документацию и сделать поведение бота прозрачным для пользователя и администратора.

## Принципы
- Минимальные и целевые изменения, без «золотого покрытия».
- Единый источник истины для конфигурации и типов.
- Порядок операций: фильтрация → ограничение (`k`) → форматирование → вывод.
- Возврат главного меню после пользовательских действий, где это ожидаемо.
- Не правим нерелевантные баги и не меняем публичное API без явной необходимости.

## Быстрые исправления (выполнено)
- Добавлена кнопка «Закрыть настройки» в `buildSettingsKeyboard` и обработчик `close:settings` → возвращает главное меню.
- Добавлен общий обработчик `bot.on('message')` → для любых сообщений показывает основное меню.
- Исправлен порядок в «Последние»: `type`-фильтрация до `k` (в `fetchLatestVideos` + упрощён хендлер `🆕 Последние`).
- Обновлён текст помощи (ранее): упор на клавиатуру, без слэш-команд; `k` конфигурируется до `SEARCH_MAX_K`.
- Скрытая команда `/admin` (ранее): листинг доступных админ-команд для `env.ADMIN_USER_ID`.

### Проверка выполненных исправлений
- «Настройки» → «Закрыть настройки»: закрывает инлайн-клавиатуру, показывает главное меню.
- Любое сообщение вне режима поиска: бот отвечает «Выберите действие…» с главным меню.
- «Последние» при выбранном `type` и `k`: выводит ровно `k` видео нужного типа.

## Этапы рефакторинга

### Этап 1. Конфигурация и валидация окружения
- Централизовать доступ к `env` в `src/config/env.js`; описать обязательные ключи.
- Ввести раннюю валидацию: наличие `TELEGRAM_BOT_TOKEN`, `YOUTUBE_API_KEY`, корректность диапазонов `k`, `threshold`.
- Зафиксировать единые имена: `SEARCH_MAX_K`, `SEARCH_MAX_DISTANCE`, и использовать их везде.
- Артефакты: схема `env`, проверка при старте, понятные сообщения об ошибках.
- Критерии: отсутствие расхождений имён, единая точка проверки.

### Этап 2. Интерфейсы данных видео
- Единый тип: `{ id, title, description, url, type, channelId?, publishedAt?, score? }`.
- Привести нормализацию описаний и `deriveType` к одному месту (`services/youtube/classify`, `services/text/*`).
- Убрать дубли нормализации в скриптах индексации.
- Критерии: все места получения видео возвращают один тип.

### Этап 3. Хранилище настроек пользователя
- Проверить/привести `settings_store`: типы и дефолты (`k ≥ 1`, `k ≤ SEARCH_MAX_K`, числовой `threshold`).
- Единообразно применять настройки в `Поиск`, `Последние`, `Настройки`, `Помощь`.
- Критерии: одинаковая трактовка настроек во всех хендлерах.

### Этап 4. Логика «Последние»
- Закрепить порядок: выбор канала → ids → детали → `type`-фильтр → `slice(0, k)` → форматирование → вывод.
- Проверить скрипты (`index_latest_10.js`, `preview_latest_10.js`) на согласованность.
- Критерии: отсутствие пост-фильтрации после `slice`, одинаковый результат при одинаковых входных.

### Этап 5. Поиск (LanceDB)
- Унифицировать доступ к таблицам и метрикам: один ключ (`score` или `_distance`).
- Вынести конструирование поиска в модуль: параметры `k`, `threshold`, `channelId`, `type`.
- Поддержать `showScore` единообразно в форматтерах.
- Критерии: консистентные результаты и одинаковый формат вывода.

### Этап 6. Обработчики Telegram
- Ревизия всех `bot.hears`/`bot.on`/`bot.command`: единый стиль текстов и возврата клавиатуры.
- Централизовать показ главного меню (общий обработчик + минимизация дублей в специфических местах).
- Критерии: нет повторных сообщений меню; предсказуемые переходы.

### Этап 7. Форматирование вывода
- Один форматтер для «Последние» и один для поиска; `showScore` управляет показом балла.
- Критерии: отсутствие разночтений, удобочитаемость.

### Этап 8. Админ-команды
- Перечень операций и единый роутер исполнения: блокировки/статистика/таблицы/проверки/индексации.
- Проверка доступа по `env.ADMIN_USER_ID`, единые ответы об успехе/ошибках.
- Критерии: корректный контроль доступа, стабильный вывод.

### Этап 9. Логи и ошибки
- Единые уровни (`debug/info/warn/error`) и контекст (userId, channelId).
- Чёткие сообщения при ошибках YouTube/LanceDB.
- Критерии: информативные логи, отсутствие «тихих» падений.

### Этап 10. Тестирование и проверки
- Юнит-тесты: `deriveType`, нормализация описаний, `fetchLatestVideos`, парсинг параметров поиска.
- Интеграционные: поток «Последние», поиск с `threshold` и `type`.
- Скрипт самопроверки окружения: env, соединение с LanceDB, доступность YouTube API.
- Критерии: зелёные тесты на критических путях; чёткая диагностика окружения.

### Этап 11. Документация
- Обновить `README`: настройки, переменные окружения, примеры команд, ограничения `k`/`threshold`, поведение клавиатур.
- Раздел «Админ»: настройка каналов, запуск индексации, диагностика.
- Критерии: актуальность и полнота, отсутствие противоречий.

## Точки касания кода
- `src/index.js` — хендлеры, клавиатуры, форматтеры.
- `src/config/env.js`, `src/config/logger.js` — конфигурация и логирование.
- `src/services/youtube/*` — клиент, классификация, нормализация.
- `src/services/vector/lancedb/*` — таблицы и поиск.
- `src/services/user/*` — настройки и хранилище.
- `src/services/admin/*` — админ-функции.
- `src/scripts/*` — индексация, предпросмотр, утилиты.

- Возможны переименования env-переменных. Нужна памятка и скрипт проверки.
- Важно сохранить совместимость поведения для пользователей.

- Предсказуемость вывода «Последние» (тип → k) — 100%.
- Снижение дублирующего кода в форматтерах и хендлерах.
- Единые тексты и клавиатуры без повторов.
- Чёткая диагностика проблем окружения.
