# План работ: Телеграм‑бот с RAG для релевантных YouTube‑видео

## Цель
- Реализовать бота на Node.js, который синхронизирует видео выбранного YouTube‑канала по команде администратора и выполняет семантический поиск по названию и описанию, возвращая `title`, `description`, `https://youtu.be/<videoId>`.

## Архитектура
- Телеграм‑бот: обработка команд и сообщений, разграничение прав администратора.
- YouTube Fetcher: получение списка видео и метаданных по каналу.
- RAG Indexer: генерация эмбеддингов, сохранение в векторном хранилище.
- RAG Search: семантический поиск и ранжирование.
- БД метаданных: `SQLite` (через `drizzle-orm`).
- Конфигурация: `.env` с токенами и параметрами.

## Стек
- Node.js (JavaScript), `telegraf` или `grammY`.
- YouTube Data API v3: `googleapis` или `axios`.
- RAG: `langchain`.
- Эмбеддинги: `mistral.ai` https://docs.mistral.ai/guides/rag/.
- Векторное БД: `lancedb` (локально) или `pinecone` или использовать возможности `mistral.ai`.
- ORM: `drizzle-orm` + `SQLite`. Логи: `pino`. Конфиг: `dotenv`. Тесты: `vitest`.

## Структура проекта
- `src/config/` — загрузка `.env`, константы.
- `src/bot/` — инициализация бота, регистрация команд.
- `src/services/youtube/` — запросы к YouTube API, адаптер канала.
- `src/services/rag/` — индексация и поиск, обёртки над эмбеддером и векторным БД.
- `src/db/` — модель таблиц `videos`, подключение и миграции `drizzle`.
- `src/utils/` — утилиты: парсинг каналов, форматирование ответа, ретраи.
- `src/index.ts` — точка входа (polling/webhook).
- `tests/`, `scripts/`.

## Переменные окружения
- `TELEGRAM_BOT_TOKEN`, `ADMIN_USER_ID`, `YOUTUBE_API_KEY`.
- `EMBEDDINGS_PROVIDER` (`mistral.ai`), `MISTRAL_API_KEY`.
- `VECTOR_DB` (`lancedb`), `LANCEDB_DIR`.
- `DATABASE_URL` (напр. `./data/db.sqlite`).

## Команды бота
- `/start` — приветствие.
- `/help` — справка.
- `/sync_channel <url|@handle|channelId>` — админ‑синхронизация канала.
- `/status` — админ‑состояние индекса/квоты.
- Поиск: любое текстовое сообщение; альтернатива `/search <запрос>`.

## Схема данных
- Таблица `videos`:
  - `id` (`videoId`, PK), `channel_id`, `title`, `description`, `url`, `published_at`, `etag`, `last_indexed_at`.
- Векторная коллекция `video_embeddings`:
  - ключ `videoId`, вектор, метаданные (`title`, `description`, `channel_id`, `published_at`, `url`).

## Алгоритм синхронизации YouTube
- Разрешение `channelId` из URL или `@handle` через `channels.list`.
- Получение плейлиста `uploads` (`contentDetails.relatedPlaylists.uploads`).
- Пагинация `playlistItems.list` (maxResults=50) → сбор `videoId`, `publishedAt`.
- `videos.list(part=snippet, id=...)` → `title`, `description`, `etag`.
- Upsert метаданных в `SQLite` (по `videoId`).
- Подготовка документов `[title]\n\n[description]` для эмбеддинга.
- Batch‑индексация в векторное БД, пропуск уже индексированных по `etag/last_indexed_at`.

## Индексация (RAG)
- Нормализация: трим/очистка лишнего в описании; сохранение исходного текста.
- Эмбеддинги: мультиязычная модель; контроль batch‑размера.
- Сохранение: вектор + метаданные в коллекцию.
- Валидация: выборка и ручная проверка топ‑K.

## Поиск (RAG)
- Эмбеддинг запроса той же моделью.
- Поиск `topK` (5–10), опционально фильтры по каналу.
- Ранжирование: повышенный вес заголовка; порог `similarity`.
- Ответ: `title`, `description`, `https://youtu.be/<videoId>`; пагинация при множестве результатов.

## Администрирование
- Проверка `ctx.from.id === ADMIN_USER_ID` для `/sync_channel` и `/status`.
- Rate‑limit и очередь задач синхронизации.
- Логирование попыток доступа неадминов.

## Ошибки и квоты
- YouTube: backoff, ретраи на 429/5xx, экономия квоты.
- Telegram: ретраи отправки, обработка timeouts.
- Индексация: запись неуспешных `videoId` для повторов; отчёт админу.

## Тестирование
- Юнит‑тесты: парсинг канала, преобразование сущностей → документ.
- Интеграционные: поиск по фикстурам (10–20 видео), проверка ранжирования.
- Моки YouTube API. Инструменты: `vitest`.

## Сборка и запуск
- Скрипты: `npm run dev` (polling), `npm run build`, `npm run start`.
- `.env` заполнить токенами/ключами; Node LTS.

## Деплой
- Prod: `webhook` (HTTPS, домен/сертификат), `setWebhook`.
- Логи и алерты: отправка админу ошибок через бот.

## Шаги реализации и критерии приёмки
1) Инициализация проекта (JS, линтер, `dotenv`, `pino`).
2) Бот `/start`, `/help`; запуск в `polling`.
3) Админ‑мидлвар; защита `/sync_channel`, `/status`.
4) Парсинг канала (URL/`@handle` → `channelId`) + тесты.
5) Загрузка `uploads` + пагинация; сбор `videoId`, `publishedAt`.
6) `videos.list(snippet)`; upsert в `SQLite`.
7) Инициализация векторного БД; схема коллекции.
8) Эмбеддинги (провайдер, батчи); upsert в коллекцию.
9) Обработчик поиска; выдача `title`, `description`, `url`.
10) Ранжирование/порог; корректный отбор.
11) `/status` отчёт (кол-во видео, дата последней синхронизации, ошибки).
12) Тесты зелёные; базовое покрытие.
13) Логи/ретраи; отсутствие необработанных исключений.
14) Документация `README.md` (установка, переменные, команды).

## Риски и митигация
- Квоты YouTube → батчи, кеш, ограничение частоты.
- Мультиязычность → подобрать модель с поддержкой RU.
- Большой объём → инкрементальная индексация, дедуп по `videoId`.
